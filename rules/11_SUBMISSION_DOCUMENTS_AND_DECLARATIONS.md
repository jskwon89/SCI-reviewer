# 11. 제출문서·선언문 작성 범위

타이틀페이지, 커버레터, Data Availability 및 AI 사용 선언을 작성·수정·검토할 때 적용한다. 필요한 정보를 정확히 전달하고, 저자가 요청하지 않은 설명이나 이행 약속을 덧붙이지 않는다. 이 규칙은 제출 부속문서의 범위를 정하며, 본문의 이론·논의·함의를 충분히 발전시키는 원칙을 축소하지 않는다.

## 1. 타이틀페이지

- 기본 구성은 논문 제목, 저자명·소속, 교신저자 연락처, ORCID, 필요한 단어 수와 저자 기여이다.
- Running head, funding 등은 실제 저널 요구, 제출 방식, 사용자의 지시에 맞는 위치에 둔다. 모든 선언을 표지에 자동으로 모으거나 여러 파일에 반복하지 않는다.
- 장황한 연구 소개, 자기평가, 내부 검수 결과, 수정 이력, 불필요한 개인정보를 추가하지 않는다.
- 별도 타이틀페이지인지 저자정보 포함 원고의 첫 페이지인지 실제 포털의 파일 구분에 맞춘다.

## 2. 커버레터

- 투고 요청과 논문 제목·유형, 연구문제와 자료, 핵심 결과·기여, 목표 저널과의 관련성, 사실에 맞는 독창성·미출판·비동시투고 진술, 짧은 맺음말과 연락처를 중심으로 쓴다.
- 필요할 때만 제출 파일을 간단히 안내한다. 통상 1쪽 안에서 자연스럽게 설명하며, 형식적으로 분량을 채우지 않는다.
- 내부 QA, 긴 분석 목록, 수정 이력, 예방적 방어문, 일반적인 중요성 수사를 덧붙이지 않는다.
- 최초 투고용 편지에 리비전 경위를 넣지 않는다. 수정투고 편지에는 편집자에게 필요한 변경 요지만 쓰고 자세한 대응은 응답서에 둔다.
- 저널이 요구하지 않는 윤리·동의·AI·공개 선언을 관행이라는 이유만으로 반복 삽입하지 않는다. 확인되지 않은 독창성·동의·승인 사실을 만들어 쓰지 않는다.

## 3. 데이터·자료·코드 제공 약속

- 코드 제공, 공개 저장소 등록, 게재 승인 후 공개, 요청 시 자료 제공을 기본 문구로 넣지 않는다.
- “available upon reasonable request”, “code will be deposited”, “data and code are available from the author” 등 저자의 이행 의무를 만드는 표현은 사용자의 별도 명시적 결정 없이 추가하지 않는다.
- 제공받은 2차 자료는 실제 제공기관·원출처·접근 방법과 확인된 이용 조건을 설명한다. 저자가 원자료를 직접 제공하거나 재배포할 것처럼 쓰지 않는다.
- 코드에 관한 문구가 요구되지 않았다면 공개 약속뿐 아니라 불필요한 비공개 선언도 추가하지 않는다.
- 포털의 일반적인 데이터 정책 표시를 저자의 재배포 권한이나 코드 제공 동의로 해석하지 않는다. 공식 요구와 충돌하는 경우 해당 요구와 이용 조건을 정확히 설명하고, 허위 약속이나 동의로 대신하지 않는다.
- 이 원칙은 본문, 타이틀페이지, 커버레터, 부록, 포털 입력문에 동일하게 적용한다.

## 4. AI 사용 선언

사용자가 확인한 사용 범위는 다음과 같이 구체적으로 적는다.

> 제출 파일 정리·검수, 영문 번역 및 문장 교정

이 범위에 해당할 때 사용할 기본 영문은 다음과 같다.

> OpenAI’s ChatGPT was used to prepare and check the submission files, translate the manuscript into English, and edit its language. The author is responsible for the accuracy of the translation and the integrity of the final manuscript, including its references.

- 도구·모델명은 실제 사용 정보와 사용자가 확인한 표기에 맞춘다. 특정 모델명을 모든 논문에 일괄 적용하지 않는다.
- “drafting and revising manuscript text”처럼 사용 범위를 초안 작성·내용 개발까지 넓히는 표현으로 바꾸지 않는다.
- 아이디어 생성, 문헌 검증, 분석·코드 작성·실행 등의 용도를 확인 없이 추가하지 않는다. 반대로 실제 사용 사실과 다른 축소·부정 진술도 만들지 않는다.
- 저널이 별도로 요구하는 항목은 실제 요구와 사실에 맞는 최소한의 문구만 추가한다. 약관 검토나 준수 여부를 확인하지 않고 완료했다고 선언하지 않는다.
- AI 선언을 문체 방어문이나 작성 과정 설명으로 늘리지 않는다.

## 5. 짧은 완료 점검

- 타이틀페이지·커버레터에 필요한 정보와 저널 적합성이 분명한가?
- 내부 검수 문구·수정 흔적·불필요한 선언을 덧붙이지 않았는가?
- 원자료의 제공기관과 저자의 역할을 혼동하지 않았는가?
- 코드 제공·저장소 등록·요청 시 자료 제공 약속을 임의로 넣지 않았는가?
- AI 사용 문구가 확인된 범위를 정확히 표현하는가?
- Running head는 원고·포털 간에 같고 실제 글자 수 제한 안에 있는가?

이 점검을 이유로 새 분석, 별도 문헌 수집, 전체 원고의 반복 검수를 요구하지 않는다.
