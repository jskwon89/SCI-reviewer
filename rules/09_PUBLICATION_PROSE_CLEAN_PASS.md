# 09. Publication-Prose Clean Pass

## 0. 목적

이 단계는 분석의 타당성을 다시 검증하는 단계가 아니라, 제출 원고가 **연구 자체를 설명하는 글**로 읽히는지 최종 점검하는 단계다.

특히 다음 네 가지를 제거한다.

- reviewer를 선제적으로 설득하려는 과도한 방어문
- 실제 대상이 보이지 않는 추상적·명사화된 문장
- 동일한 수사 틀을 반복하는 기계적 문체
- revision/QA/audit 과정이 publication-facing manuscript에 남은 흔적

작성·수정·독립검토의 마지막 단계에서 반드시 수행한다.

---

## 1. Sentence-purpose test

각 문장에 먼저 묻는다.

> 이 문장은 현재 연구의 문제, 자료, 방법, 결과, 해석 또는 한계를 설명하는가?
> 아니면 저자가 어떻게 검토·수정·방어했는지를 설명하는가?

후자라면 원칙적으로 삭제하거나 publication-facing 문장으로 다시 쓴다.

예:
- "Additional sensitivity checks conducted during revision..."
  → "Four sensitivity analyses examined..."
- "The retained specification continued to..."
  → 현재 분석을 직접 설명
- "To address this concern, we additionally..."
  → 무엇을 왜 분석했는지를 연구질문 관점에서 직접 설명

Response letter의 역사를 manuscript의 논리로 사용하지 않는다.

---

## 2. Defensive writing: 필요한 경계와 선제 방어를 구분한다

모든 caveat를 제거하지 않는다.

### 유지해야 하는 boundary
이 문장이 없으면 독자가 결과의 범위·설계·측정·인과성·일반화 가능성을 실질적으로 오해할 가능성이 큰 경우.

예:
- 횡단자료이므로 temporal order를 확정할 수 없음
- area mean이 독립적으로 관찰된 neighborhood property가 아님
- exploratory analysis가 causal mediation을 입증하지 않음

### 삭제·축약할 가능성이 큰 defense
- reviewer가 할 법한 반론을 하나씩 예상해 부정하는 문장
- 같은 제한을 Introduction, Method, Results, Discussion에서 반복
- 중심 결과보다 "무엇을 의미하지 않는지"가 더 길게 설명됨
- 결과와 직접 관계없는 통계모형/대안해석을 선제적으로 부정
- response letter에서 필요한 문장이 본문에 그대로 들어옴

원칙:
**CLAIM FIRST → ONE NECESSARY BOUNDARY → MOVE ON.**

동일한 한계는 가장 적절한 위치에서 충분히 한 번 설명하고, 다른 절에서는 필요할 때만 짧게 참조한다.

---

## 3. Abstract-to-concrete test

다음과 같은 추상 주어가 연속되면 실제 대상을 복원한다.

- this pattern
- this distinction
- these considerations
- this interpretation
- these findings
- this relationship
- this framework
- the contextualization / differentiation / interpretation

독자가 바로 앞 문장을 다시 읽어야 선행사를 찾을 수 있으면 FAIL이다.

가능하면:
- 실제 변수
- 실제 집단
- 실제 비교
- 실제 결과
- 실제 행위자
를 문장의 주어 또는 목적어로 쓴다.

예:
- "This pattern suggests..."
  → "The steeper fear–symptom slope in high-cohesion areas suggests..."
- "This distinction is important..."
  → "Lower average symptom levels and weaker fear-related slopes are different empirical claims."

추상어를 쉬운 단어로 바꾸는 것만으로는 충분하지 않다. **무엇이 무엇과 어떻게 관련되는지**가 보여야 한다.

---

## 4. Mechanical-template test

기계적 문체는 특정 단어의 존재가 아니라 **반복되는 구조**로 판단한다.

점검:
- 모든 문단이 claim → caveat → implication 순서인가?
- subsection마다 "These findings..."로 끝나는가?
- Although / While / Rather / Taken together가 반복되는가?
- 세 항목 병렬구조를 습관적으로 반복하는가?
- 모든 결과에 같은 수의 설명·한계·함의를 붙이는가?
- 문장 길이와 문단 길이가 지나치게 균일한가?

수정할 때 동의어만 바꾸지 않는다.
각 문단의 실제 기능에 따라 문장 구조 자체를 다시 설계한다.

---

## 5. Internal QA / revision-trace sweep

다음 표현은 자동 삭제어가 아니라 **경고어**다.

- final / finalized
- revised
- clarified
- retained
- corrected
- baseline
- current / previous / original
- harmonized
- validation / audit
- reconciliation
- write-back
- flagged
- version
- during revision
- additional check requested
- to address this concern

판정 질문:
> 이 표현의 대비대상이 현재 논문 독자에게 명시되어 있는가?
> 그 대비가 연구 자체를 이해하는 데 필요한가?

둘 다 아니면 revision trace로 보고 다시 쓴다.

### 정상적 사용의 예외
다음과 같은 표준 학술표현은 문맥상 자족적이면 허용한다.

- primary analysis
- sensitivity analysis
- final analytic sample
- current study
- original scale item
- baseline measurement (실제 종단설계의 baseline)
- revised instrument (공식적으로 개정된 도구를 지칭)

즉 **단어 자체를 금지하지 않는다. 이전 버전/QA 역사를 암시할 때만 문제다.**

---

## 6. Positive-definition test

범주·변수·분석을 다음 순서로 설명한다.

1. 무엇인가
2. 어떻게 측정/구성했는가
3. 필요한 예시
4. 필요한 경우에만 무엇이 아닌가

다음과 같은 exclusion chain이 정의의 중심이 되면 다시 쓴다.

> It is not X, does not include Y, and should not be interpreted as Z.

독자는 먼저 대상의 실체를 알아야 한다.

---

## 7. Reviewer output must be sentence-level

문체 문제를 발견했을 때 다음처럼만 쓰지 않는다.

- "방어적이다."
- "추상적이다."
- "AI-like하다."
- "내부 검수 문장이 있다."

반드시 가능한 범위에서 다음을 함께 제시한다.

1. **실제 위치/문장**
2. **문제 유형**  
   DEFENSIVE / ABSTRACT / TEMPLATE / REVISION-TRACE / INTERNAL-QA / OVER-SIGNPOSTING
3. **왜 publication prose에서 문제가 되는지**
4. **조치**  
   DELETE / SHORTEN / MOVE / REWRITE
5. **가능하면 publication-facing 대체문**

MINOR 또는 MAJOR 판정을 할 정도의 문제가 있다면 대표 사례를 실제 문장 단위로 제시한다. 단순 빈도만으로 판정하지 않는다.

---

## 8. Final clean-pass sequence

최종 제출 전 다음 순서로 한 번 더 읽는다.

1. **DELETE** — 중복·meta prose·reviewer-response caveat
2. **CONCRETIZE** — 추상 주어를 실제 대상과 결과로 교체
3. **DE-TEMPLATE** — 반복 rhetorical frame 제거
4. **DE-CONTAMINATE** — revision/QA history 제거
5. **BOUNDARY CHECK** — 필요한 한계까지 과잉 삭제하지 않았는지 확인
6. **AUTHOR VOICE / FIELD NORM** — 저자와 목표 저널의 정상 문체로 보정

이 pass에서 새로운 분석이나 새로운 이론을 추가하지 않는다.
