# Publication-Prose Clean Pass Checklist

제출 직전 manuscript를 이전 버전·reviewer response·분석 로그를 보지 않은 독자처럼 다시 읽는다.

## Sentence purpose
- [ ] 각 문장이 현재 연구 자체를 설명한다.
- [ ] 저자가 무엇을 수정·검증·확인했는지를 설명하는 meta prose가 남아 있지 않다.
- [ ] "during revision", "to address this concern", "retained specification" 같은 revision-history 문구가 publication-facing 문장으로 정리됐다.

## Defensive writing
- [ ] 핵심 주장 뒤에는 필요한 boundary만 남아 있다.
- [ ] not X / does not imply Y / should not be interpreted as Z가 연속되지 않는다.
- [ ] 같은 제한을 여러 section에서 반복하지 않는다.
- [ ] reviewer가 제기할 법한 모든 반론을 선제적으로 막으려 하지 않는다.
- [ ] 필요한 설계·측정·인과성 한계는 삭제하지 않았다.

## Concreteness
- [ ] this pattern / this distinction / these findings 같은 추상 주어의 실제 대상이 즉시 보인다.
- [ ] nominalization이 실제 행위자·변수·결과를 숨기지 않는다.
- [ ] 독자가 앞 문장으로 되돌아가야만 선행사를 알 수 있는 지시어가 없다.
- [ ] 결과와 함의를 실제 비교·집단·변수로 표현했다.

## Mechanical style
- [ ] 모든 문단이 claim → caveat → implication의 동일 틀을 갖지 않는다.
- [ ] 동일 opener·transition·3항 병렬 구조가 습관적으로 반복되지 않는다.
- [ ] 동의어 치환만으로 반복 구조를 숨기지 않았다.
- [ ] 문단의 실제 기능에 따라 문장 구조가 달라진다.

## Internal QA / revision trace
- [ ] final / revised / retained / corrected / baseline / previous / original / validation / audit 등이 이전 버전이나 QA history를 암시하지 않는다.
- [ ] analysis log, correction history, reviewer-response logic이 manuscript에 스며들지 않았다.
- [ ] 표준 학술표현(primary analysis, sensitivity analysis, final analytic sample 등)은 문맥상 자족적으로 사용됐다.
- [ ] 경고어를 기계적으로 삭제하지 않고 문맥으로 판정했다.

## Definition order
- [ ] 변수·범주·분석은 무엇인지 먼저 정의한다.
- [ ] exclusion chain이 정의를 대신하지 않는다.
- [ ] 필요한 예외·제외는 positive definition 뒤에 온다.

## Reviewer evidence
- [ ] 문체 문제를 판정했다면 실제 문장 또는 위치를 제시했다.
- [ ] DEFENSIVE / ABSTRACT / TEMPLATE / REVISION-TRACE / INTERNAL-QA를 구분했다.
- [ ] 문제 문장마다 DELETE / SHORTEN / MOVE / REWRITE 중 조치를 제안했다.
- [ ] 가능하면 publication-facing 대체문을 제시했다.
- [ ] 단어 빈도만으로 AI-like/방어적 문체를 단정하지 않았다.

## Final gate
- [ ] 원고가 response letter나 analysis memo가 아니라 하나의 완성된 논문처럼 읽힌다.
- [ ] 정확성은 유지하면서도 과도하게 방어적·추상적·기계적이지 않다.
- [ ] 수정 후 의미·수치·인용·분석 범위가 바뀌지 않았다.
