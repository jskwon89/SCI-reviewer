# Revision Implementation Checklist

## Comment triage
- [ ] 각 comment를 structure / theory / method / analysis / results / writing / reporting으로 분류했다.
- [ ] reviewer의 문제 진단과 제안 문장을 구분했다.
- [ ] 새 분석이 정말 필요한지 검토했다.

## Scope
- [ ] primary contribution이 바뀌었는지 확인했다.
- [ ] 바뀌었다면 옛 theory/H/terminology를 제거했다.
- [ ] secondary 분석을 불필요하게 승격하지 않았다.

## Manuscript contamination
- [ ] previous/revised/final/clarified/retained/corrected 등 revision-history 흔적을 점검했다.
- [ ] response-letter 논리를 본문에 그대로 옮기지 않았다.
- [ ] 같은 caveat를 여러 section에 반복하지 않았다.
- [ ] old/new terminology가 혼재하지 않는다.

## Style
- [ ] reviewer comment마다 동일한 문장틀을 추가하지 않았다.
- [ ] These findings / Taken together / Importantly 등의 반복을 점검했다.
- [ ] 수정 후 전체 원고가 하나의 voice로 읽힌다.
- [ ] author-voice baseline과 크게 어긋나지 않는다.

## Depth
- [ ] 구조 문제를 새 문장 추가만으로 덮지 않았다.
- [ ] 불필요한 분석/이론을 줄이고 필요한 conceptual bridge를 보강했다.
- [ ] Method가 이미 길다면 더 늘리지 않았다.
- [ ] Discussion과 Conclusion의 substantive depth를 확인했다.

## Final
- [ ] 이전 버전을 모르는 독자가 현재 원고만으로 이해할 수 있다.
- [ ] 실제 blocker가 아닌 부분은 더 건드리지 않았다.
